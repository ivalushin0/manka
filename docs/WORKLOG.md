# Журнал работ Manka

## Не повторять
- Для WhatsApp/Meta не искать «стратегию обхода»: старые адреса Meta (31.13.x, 157.240.x) режутся по адресу, соединение не устанавливается — обход тут бессилен (замер: 0/10 и без обхода, и с обходом). Работает подмена на сеть 57.144.0.0/14 + обход.
- Не проверять сеть «от имени приложения» (`su <uid> curl`), пока оно закрыто: Android режет сеть закрытым приложениям (APP_BACKGROUND), результат будет ложным. Сначала открыть приложение.
- Не подменять адреса «для всех» раньше перенаправления в ByeDPI: в режиме ByeDPI подмена только для самого ciadpi (uid 0).
- Не писать русские строки через PowerShell-скрипты из bash: ломается кодировка. Только Edit.

## 2026-09-30 — WhatsApp глючит (сообщения, картинки, голосовые)
- WhatsApp был в исключениях Manka → шёл без обхода.
- Замеры подключений к 443 (по 10 попыток): 31.13.72.48 (чат) 0/10, 31.13.72.52 0/10, 157.240.205.60 0/10, IPv6 Meta 6/10, 57.144.249.32 10/10 — одинаково с обходом и без.
- 57.144.249.32 отдаёт все имена WhatsApp/Instagram/Facebook с верным сертификатом; без обхода — таймаут (режут и по имени).
- Решение: модуль META_FIX — DNAT заблокированных сетей Meta на рабочий адрес 57.144.x (выбирается при старте и смене сети), IPv6 Meta отклоняется; WhatsApp убран из исключений. Проверено на Wi-Fi и LTE: WhatsApp подключается, адреса открываются за 0,3–1,3 с.
- Пользователь не захотел пускать WhatsApp через сервер Xray (КЗ).
