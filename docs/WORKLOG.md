## Не повторять
- Для WhatsApp не искать «стратегию обхода»: его чат 31.13.72.48 режется по адресу (0/10 с обходом и без). Работает подмена на 57.144.x + обход — но ТОЛЬКО для WhatsApp: 57.144.x отдаёт заглушку 404 для Instagram/Facebook.
- Проверяя «работает ли адрес», смотреть размер ответа, а не только код и сертификат: заглушка 404/363 Б ≠ рабочий сервис.
- Не проверять сеть «от имени приложения» (`su <uid> curl`), пока оно закрыто: Android режет сеть закрытым приложениям (APP_BACKGROUND), результат будет ложным. Сначала открыть приложение.
- Не подменять адреса «для всех» раньше перенаправления в ByeDPI: в режиме ByeDPI подмена только для самого ciadpi (uid 0).
- Не писать русские строки через PowerShell-скрипты из bash: ломается кодировка. Только Edit.

Настоящие адреса Instagram/Facebook (31.13.72.53/.174/.8) открываются через обход. Заблокирован только чат WhatsApp 31.13.72.48.
- Исправление: подмена только для приложений WhatsApp (META_UIDS: com.whatsapp, com.whatsapp.w4b); в режиме ByeDPI выключена (не отличить приложения).
- Telegram: на TrapHata прямой фронт 149.154.167.220 теперь 0/10 (было 8/10), все 10 проверенных адресов Telegram мертвы; Cloudflare-домены работают. Прокси с ip-fail-cooldown 60 каждую минуту терял 3 с на мёртвый адрес.
- Исправление: модуль проверяет --dc-ip адреса (старт, смена сети, раз в 30 мин из netwatch, команда tgws-check) и при недоступности запускает прокси без --dc-ip (только Cloudflare). Статус tgws_direct, подпись на экране Telegram.

## 2026-10-03 — аудит и облегчение (0.1.0-42)
Решения пользователя: наборы Remba и KDS оставить (нужны другим сетям/телефонам), остальное чистить; DNS через Xray НЕ делать; магазин оставить (через него приходят обновления наборов).
- Наборы: удаляется всё, на что не ссылается ни одна стратегия (Windows-драйверы, .ps1, bak/, hosts, заметки): Remba 22 → 10,4 МБ. Чистка и при сборке APK (fetch-store.sh), и при установке/обновлении (KitCleaner). Полная копия только у модуля, у приложения — описания (compactKits один раз для старых установок).
- APK: модуль только arm64 (32-битные качают полный модуль из релиза), урезанный Xray из исходников 36,5 → 32,6 МБ (меньше не выходит: разбор конфига тянет все протоколы, вкл. WireGuard/gVisor). Итог APK 34,0 → 23,2 МБ.
- KernelSU держал копию модуля в modules_update (50 МБ) и после перезагрузки откатил бы живой модуль на неё — теперь удаляется после установки.
- Модуль: перезапуск движка только при изменении (engine_sig); скрипт разбит на lib/*.sh; проверка прямых адресов Telegram (tgws-check, tgws-probe).
- Списки адресов (Meta, Telegram, Gemini) — net/manka-net.json в репозитории, телефон берёт раз в сутки (NetLists).
- Интерфейс: цветная кнопка, сводка профиля + отдельный экран «Профиль и стратегии», сервисы с WhatsApp/Telegram/Gemini и окном «что не открылось», простой режим автоподбора, «Gemini через свой сервер · KZ», крупнее подсказки.
- Тесты: CoreLogicTest (порты, профили — сверка с md5 модуля, склейка стратегий сервисов, списки адресов, чистка наборов).

### Не повторять
- В урезанном Xray нельзя убирать main/confloader/external — без него не читается файл конфига (EOF).
- В bash-циклах под set -e/pipefail не писать `[ условие ] && cmd` последней командой — ложное условие роняет скрипт.
- В Kotlin внутри кода, где есть переменная `app`, не писать полные имена `app.manka...` — перекрывает пакет. Только import.
